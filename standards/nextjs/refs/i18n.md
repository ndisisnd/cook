# Internationalization

Use this ref for locale routing, dictionaries, locale detection in `proxy.ts`, SEO alternates, and `next-intl` (4.x, current as of 2026-10).

## Workflow: App Router With `next-intl`

1. Install `next-intl`; create `messages/en.json` and one file per locale.
2. Define locales once in `src/i18n/routing.ts` with `defineRouting`.
3. Detect locale in `src/proxy.ts` with `next-intl/middleware`.
4. Put routes under `app/[locale]/`; the root layout is `app/[locale]/layout.tsx`.
5. Load messages server-side in `src/i18n/request.ts`.
6. Add `hreflang` alternates in `generateMetadata`.
7. Pre-render locales with `generateStaticParams`; run `next build` and confirm each locale path renders.

```ts
// src/i18n/routing.ts
import { defineRouting } from 'next-intl/routing';

export const routing = defineRouting({ locales: ['en', 'fr', 'vi'], defaultLocale: 'en' });
```

```ts
// src/proxy.ts (was middleware.ts before Next.js 16)
import createMiddleware from 'next-intl/middleware';
import { routing } from './i18n/routing';

export default createMiddleware(routing);

export const config = { matcher: '/((?!api|trpc|_next|_vercel|.*\\..*).*)' };
```

- Prefer URL-first locale routing for SEO. Use one URL pattern consistently.
- Pages Router uses the `i18n` key in `next.config.js` instead.
- Without a library, follow the same shape: `app/[lang]/`, `hasLocale` check plus `notFound()`, a `server-only` `getDictionary`.

## Server-Side Messages

```ts
// src/i18n/request.ts
import * as rootParams from 'next/root-params';
import { notFound } from 'next/navigation';
import { getRequestConfig } from 'next-intl/server';
import { hasLocale } from 'next-intl';
import { routing } from './routing';

export default getRequestConfig(async ({ locale }) => {
  if (!locale) {
    const param = await rootParams.locale();
    if (!hasLocale(routing.locales, param)) notFound();
    locale = param;
  }
  return { locale, messages: (await import(`../../messages/${locale}.json`)).default };
});
```

- 16.3+: `next/root-params` (stable). 16.0-16.2: enable `experimental: { rootParams: true }` in `next.config` (also on with `cacheComponents`), or use next-intl `requestLocale` (`const locale = await requestLocale`).
- Root-param getters work in Server Components only. They throw in Client Components, Server Actions, and Route Handlers. The param must be a root segment, with no `app/layout.tsx` above it.
- Validate every locale with `hasLocale` and call `notFound()` for unknown values.
- Load messages on the server. Pass only the needed namespaces to `NextIntlClientProvider`.
- Type message keys. Do not import JSON directly in components. Do not parse locale cookies on the client.

## `react-intl` (legacy apps)

- Use `useIntl().formatMessage()` for dynamic strings, `<FormattedMessage />` for static text, dot-notated keys.
- Initialize `IntlProvider` with the server-selected locale and messages to avoid hydration mismatch.

## SEO

- Generate `hreflang` alternates through the metadata API. Make canonical URLs match the locale pattern.

## Anti-Patterns

- Hardcoded user-facing strings in JSX.
- Client-side translation bundles for content that can load server-side.
- Mixed URL locale patterns.
- Unvalidated locale params.
- Inline localized conditionals such as `condition ? 'Yes' : 'No'`; use distinct keys.
